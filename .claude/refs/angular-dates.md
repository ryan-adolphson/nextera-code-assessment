# apps/web: dates and time zones

- **Dates and time zones: date-fns 4 + `@date-fns/utc` + `@date-fns/tz` (exact version).** Times are shown in **UTC by default, or the browser's zone** (Settings, `/settings`, `settings/settings-page.ts`: a `mat-button-toggle-group` `time-zone` with `time-zone-utc` / `time-zone-local` "Local (America/Chicago, UTC−6)", preview `time-zone-now`, note `time-zone-note`). **`TimeZoneSettings`** (`core/time-zone.ts`, root): `mode` (`'utc'|'local'`), `zone` (`'UTC'` or the browser zone), `ctx` (the date-fns `in` context: `utc` or `tz(zone)`), `label` ("UTC" / "local time (America/Chicago)", for "Times are …" notes), `tag` ("UTC" / "local", for column headers and "Dates (…)" labels), `offsetLabel(t)`, `setMode`; saved in localStorage `nextera.timeZone.<email>` (try/catch; anything but `local` = UTC); `FleetShell`'s constructor calls `useAccount(email)`. The browser zone comes from the `BROWSER_TIME_ZONE` token (Intl; tests pin it: `openFleet(…, role, { timeZone: 'local', browserZone })` defaults to UTC mode and `America/Chicago`). Pure helpers there: `zoneContext(zone)`, `formatIn(t, pattern, zone, withZone?)`, `zoneAbbr` ("UTC", "CST", "GMT+5:30"), `zoneOffsetMs`, `offsetLabel`, `validZone`. **Templates: never `| date: … : 'UTC'` (and no DatePipe time zones: fixed offsets, wrong across DST); use the `appTime` pipe** (`core/app-time.pipe.ts`, impure + memoised, reads `zone()` so views follow a change): `{{ t | appTime: 'MMM d, HH:mm' }}`, `: true` appends the instant's zone name ("Jan 2, 03:20 UTC" / "Jan 1, 21:20 CST"); never hard-code " UTC" / "(UTC)". **TypeScript: never `{ in: utc }` for something shown; take the zone** (`format(t, p, { in: zoneContext(zone) })`, `startOfDay`/`addDays`/`subDays`/`differenceInCalendarDays(…, { in: ctx })`), so DST days are 23/25 h; `differenceInMinutes(a, b, { roundingMethod: 'round' })`; durations are `minutesToMilliseconds`/`hoursToMilliseconds` or `millisecondsInMinute|Hour|Day` from `date-fns/constants`, never `60_000` literals, and never `t % millisecondsInDay` style alignment for anything local. Helpers: `core/days.ts` (`zoneDayOf`, `dayOf`, `pickerDate`, `defaultDays`, `dayRange`, `lastDay`, `isoDay`, `rangeError`; was `utc-days.ts`), `charts/scales.ts` (`timeTicks(from, to, width, spacing, zone)`: a tick is an instant whose wall time in the zone is a multiple of the step, scanned on the 15-min grid since every zone offset is a quarter hour, so spring-forward skips 02:00 and fall-back repeats 01:00; "MMM d" at the zone's midnight; `formatTimestamp(t, zone)`; `toCandles(points, size, zone)`: ≤ 1 h buckets by wall minutes (the repeated fall-back hour gets its own candles), 4 h buckets via `startOfDay` + `setHours` in the zone (3 h / 5 h on DST days)); `chart-tooltips.ts` (`candleSpan`/`candleTooltip`/`tooltipContent` take the zone). `LineChart` injects `TimeZoneSettings` and redraws (ticks, candles, tooltips, aria-label) on a change. Unchanged on purpose: staleness ages, the turbine page's relative windows, API/SSE ISO UTC, CSV row timestamps. **Gotcha:** with `{ in: … }` date-fns returns a `UTCDate`/`TZDate` whose getters are zoned; return epoch ms (`+date`) or ISO strings (`new Date(+d).toISOString()`: a `TZDate`'s own `toISOString` carries the offset) from helpers, as `lastDay` does. Kept by hand (no date-fns equivalent): the wall-clock tick/candle alignment above and the short candle label ("15 min", "1 h").
