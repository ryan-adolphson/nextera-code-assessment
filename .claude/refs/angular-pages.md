# apps/web: routes and pages

- **Navigation (farm first):** routes in `app.routes.ts`, with `withComponentInputBinding()`. Every page is a lazy `loadComponent` child of `FleetShell` with a `'<Page> · Nextera'` `title`.
  - **Auth (owned by `auth-engineer`, `core/auth/`):** the `FleetShell` route has `canMatch: [authGuard]` (signed out → `/login?returnUrl=…`; `/login` is a sibling outside the shell with `guestGuard`, so no `FleetStore`/SSE before sign-in, and signing out destroys the shell and closes SSE); `/reporting` has `canMatch: [roleGuard('owner')]` (a viewer → `/farms`). `AuthStore` (root) holds the session (localStorage, 24 h) and `can(minRole)`; `authInterceptor` (in `appConfig`) adds the Bearer token to `API_BASE_URL` requests and turns a 401 into sign-out → `/login`. Hide role-dependent controls with `auth.can('owner')` (the Rules page's Add/Edit/Delete and actions column; the nav filters `NAV_ITEMS` by `minRole`); the API still enforces every role (404 for too low). Roles: `core/auth/roles.ts` (mirror of `@nextera/shared`).
  - **`FleetShell` (`fleet/fleet-shell.ts` + `.html`):** the parent route and the whole page layout (`App` is just a `<router-outlet>`). It provides `FleetStore` (and `AlertRulesStore`, see Alert rules state) and calls `init()`, so the fleet loads and the SSE connection opens once, shared by its children; navigation never reconnects. It renders the error/loading states, a "Skip to content" link and `<main id="content">` (`min-w-0`, so wide tables scroll inside their `overflow-x-auto` wrapper, never the page).
  - **Side navigation (`NAV_ITEMS`: Farms `/farms`, Turbines `/turbines`, Alerting `/alerting`, Unallocated `/unallocated` and Reporting `/reporting` (owner and up; each item has a `minRole`), Settings `/settings` (every role, last, icon `settings`)), then the signed-in user (`current-user-email`, `current-user-role`) and a `sign-out` button:** `<nav id="main-nav" aria-label="Main">` with `routerLink` + `routerLinkActive` + `ariaCurrentWhenActive="page"`; the active item is styled with `aria-[current=page]:` (accent left border). Inline SVG icons (`aria-hidden`). Hooks: `data-testid="sidebar"`, `brand`, `nav-<id>`, `nav-toggle`, `main-nav`.
    - **Desktop (`md`+):** a sticky left column (`md:w-56`, `md:h-dvh`) with the app name, the live badge (`live-status`) and the nav.
    - **Narrower:** a top bar (name, live badge, menu button). The button has `aria-controls="main-nav"` and `aria-expanded`; the nav is `hidden data-open:block md:block` (`data-open` while open). Don't use the `hidden` attribute: preflight makes it `display: none !important`, which `md:block` can't override. Esc (`document:keydown.escape` host listener) closes it and refocuses the button; any `NavigationEnd` closes it. The menu expands inline (not an overlay), so Leaflet's z-indexed panes never cover it.
    - **Alert badge:** Alerting shows `FleetStore.alerts().length` as a red pill (`bg-danger text-on-danger`, `aria-hidden`) plus `sr-only` text, so the link reads "Alerting, 50 alerts" ("1 alert"; just "Alerting" at 0, no pill).
  - **`/` redirects to `/farms` (and `**` to `/farms`):** the overview lives at `/farms` so "Farms" is active (prefix match) on `/farms/:farmId` and `/farms/:farmId/turbines/:turbineId` too. Old `/` links still work. "All farms" links point at `/farms`.
  - **`/farms` → `FleetOverview`:** fleet tiles and all farms, including those without turbines. A row or link opens the farm.
  - **`/farms/:farmId` → `FarmPage`:** `farmId` is a signal input. It shows the farm tiles, the turbine map and the farm's turbines in the shared `TurbineTable` (`<app-turbine-table [turbines]="turbines()" [hiddenColumns]="['farm']">`: the `/turbines` table, filters, sorting, paging and live flash, without the Farm column; the text filter then searches turbine ids only, labelled "Turbine"), with `no-turbines` and `farm-not-found` states. It is not a `fillViewport` page: the table frame grows with its rows. Specs: `farm-page.spec.ts` (scoping, sorting, filtering, live, paging) and `fleet-routes.spec.ts`.
  - **Farm tabs:** `/farms/:farmId` is the **Overview** tab (the page above), `/farms/:farmId/history` the **History** tab (below) and `/farms/:farmId/weather` the **Weather history** tab (`FarmWeatherHistoryPage`, `weather/farm-weather-history-page.ts`); sibling routes, not children, so `/farms/:farmId/turbines/:turbineId` has no tabs. Both pages render `FarmHeader` (`fleet/farm-header.ts`: h1, location, `FarmTabs`) inside their `@if (farm())`, so an unknown farm shows only `farm-not-found`. `FarmTabs` (`fleet/farm-tabs.ts`, `FARM_TABS`) uses `PageTabs` (`ui/page-tabs.ts`: routed `mat-tab-nav-bar`, tablist "Farm", `aria-selected`, Overview `exact`; the page body goes inside `<app-farm-header>…</app-farm-header>` and lands in the tab panel; hooks `farm-tabs`, `farm-tab-overview|history|weather`). Title: the route's resolver names the farm by id, then the page sets "<name> · Weather history · Nextera" via `Title` once the farm is known. Weather history: History's date range picker (`weather-history-range`/`-from`/`-to`, "Dates (UTC|local)", max today, default `weatherDays()` = the last 7 days ending today) → a `computed` request (`{ farmId, from, to }`, `equal` by value; null for an unknown farm or a `rangeError`, shown in `weather-history-range-error`) run by an `effect` through `latestLoad` (`WeatherApi.farm(…, { interval: '30min' })`), so a range, zone (same calendar dates) or farm change sends one request. Charts: `weatherHistoryCharts(slots)` (`weather/weather.ts`, `WEATHER_HISTORY_CHARTS`: 80 m wind, 10 m wind, gusts, temperature, precipitation, humidity, pressure, cloud cover; `slotPoints` drops nulls) in a line-kind `ChartGroup` (`weather-history-charts`, `weather-history-reset-zoom`, `gapMs` 45 min so a missing bucket breaks the line, `refreshing` while reloading, domain = the loaded [from, to)). States: `weather-history-status` (role=status: loading / "N of M half-hours synced"), `weather-history-empty`, `weather-history-error` + `weather-history-retry`. Specs: `farm-tabs.spec.ts`, `weather/farm-weather-history-page.spec.ts` (`weatherHttp: true`).
  - **Farm History tab (`farm-history/`, every role):** `FarmHistoryPage` shows the farm's power output only (the API also returns wind/rotor/pitch/gearbox; not shown) as one precomputed candle per local day (`powerCandles` → `Candle` with `label` "Fri, Jan 2, 2026" and `detail` "N of M turbines reporting"; `daySpan` makes 23/25 h DST days) in a candlestick `ChartGroup` (`farm-history-charts`, `farm-history-reset-zoom`; `ChartSeries.candles` + `candleLabel: 'Daily'`). Ranges `FARM_HISTORY_RANGES` 30d / 90d / 6 months (182 days; the API allows 183 + 1 h DST slack) in `farm-history-range` (`mat-button-toggle-group`, toggles `farm-history-range-30d|90d|6m`), whole days ending today in the zone shown (`lastDays`, `FleetStore.now`). `FarmHistoryApi.daily` → `GET …/farms/:farmId/telemetry/daily?from&to&timeZone` (the browser handles its `ETag`/`no-cache`). A `computed` key (farm, range, zone, from, to; `equal` by value) runs one `latestLoad` per change; `FarmHistoryCache` (provided by `FleetShell`, so sign-out forgets it) answers the same key for `FARM_HISTORY_FRESH_MS` (15 min, client clock) without a request; Retry (`farm-history-retry`) and Refresh (`farm-history-refresh`) pass `bypass`. Status `farm-history-status` (role=status: loading / `farm-history-updated` "Updated <computedAt>." + `farm-history-note`), `farm-history-empty`, `farm-history-error`, `farm-not-found`. Specs: `farm-history/*.spec.ts` (real `HttpClient`: `TestBed.tick()` then `expectOne`; navigate with `Router.navigateByUrl`, since `whenStable()` waits for the pending load).
  - **Selection:** the turbine page selects its turbine in an `effect` on `turbineId` and clears the selection on destroy.
  - **`/turbines` → `TurbineList` (`fleet/turbine-list.ts`):** the heading and the `no-turbines` state around the shared **`TurbineTable`** (`fleet/turbine-table.ts` + `.html`; inputs `turbines` (required) and `hiddenColumns: TurbineSortKey[]`; the farm page uses it too, so change the table there, not per page). Every turbine of every farm from `FleetStore.turbines` (live, `data-updated` flash): id (→ turbine page), farm (→ farm page), `StalenessBadge`, **Commissioned** (`commissioned-cell`, `data-commissioned`: a `text-ok!` check-mark `mat-icon` (`commissioned-icon`, `aria-hidden`) when true, a `text-muted` X when false (`data-icon` check|x), sr-only "Commissioned"/"Not commissioned" either way; sorts commissioned first) power, wind, gearbox, last reading (header tag `tz.tag()`: "(UTC)" or "(local)"). Material sort headers (`sort-<key>` on the `th`, `aria-sort` ascending/descending on the sorted column and `none` on the others, default turbine id ascending; a second click reverses; turbines without readings always last; ties by id; status sorts by `STALENESS_ORDER`; alert sorts None → Info → Warning → Error like Status (best first), no reading or no rules last). Filters: text (turbine id, farm id or name, case-insensitive; `turbine-filter`; a `matIconButton matSuffix` clear button `turbine-filter-clear`, "Clear search", shown only with text, clears + resets paging + refocuses the input; the browser's own search cancel button is hidden), status (`status-filter`, `[selected]` on options), commissioning (`commissioned-filter`: Any / Commissioned / Not commissioned). Layout: the route has `data: { fillViewport: true }`, so the shell (`data-fill` on `[data-testid=shell]`, `group/shell` variants) makes the page a window-high flex column (`h-dvh`; main `min-h-0`, `overflow-y-auto` only as a fallback below the minimum) and `TurbineList`'s host (and `TurbineTable`'s inside it) is `flex min-h-0 flex-1 flex-col`: heading and filters keep their height, the `turbines-frame` (bordered, `min-h-48`) takes the rest; its `turbines-scroll` region (`role=region`, "Turbines", `tabindex=0`) scrolls the rows under a sticky header row (`sticky: true` + `bg-page`), and the paginator sits below it. `/alerting/history` (`AlertHistoryPage`, `alerting/alert-history-page.ts`) too: `AlertHistoryApi.list(from, to)`; the range is a Material date range picker (`mat-date-range-input` with `matStartDate` `history-from` / `matEndDate` `history-to`, `mat-datepicker-toggle`, `mat-date-range-picker`, `[max]` = today; `provideNativeDateAdapter()` in the page's providers) over **whole days in the zone shown** (`core/days.ts`, every helper takes the zone, default `'UTC'`: `zoneDayOf`/`dayOf` read a picked browser-local-midnight Date's Y-M-D as that day's midnight in the zone, `pickerDate` the inverse, `defaultDays` = yesterday and today, `dayRange` → `[start 00:00, end + 1 day)` (a DST day is 23/25 h), `rangeError` mirroring the API's 400s: at most 31 days, and at most 31 × 24 h, so 31 local days that gain an hour are refused with "Choose at most 30 days when the range includes a daylight-saving change."; a complete, valid range reloads, otherwise `history-range-error` and no request; a zone change keeps the picked calendar dates and reloads). Specs drive it with `MatDateRangeInputHarness` (`setValue('1/2/2026')`, en-US; `getMax()` returns ISO); `groupAlertsByTurbine(readings, farmName)` → `TurbineAlerts` (readings newest first, `latest`, `worst` level, `levelCounts` = `countByLevel` over the readings' alerts; the summary row's "Alerts" column shows one "Level: count" pill per level (`level-count`), the chips are only in the expanded readings), `paginate(turbines, 25)`; **expandable rows**: `mat-table multiTemplateDataRows`, a summary row (`history-turbine`, `data-level` = worst, `data-expanded`; `(click)` toggles, the `history-expand` button inside makes it keyboard-operable with `aria-expanded`/`aria-controls`/`aria-label` "Show|Hide readings for …", `chevron-right` icon `rotate-90`; the turbine link stops propagation) and a detail row (`history-detail`, one `detail` cell with colspan and `id=history-detail-<turbine>`, `[attr.hidden]` while collapsed + `tr.mat-mdc-row.history-detail-row` CSS: `height: auto`, `[hidden]` → `display: none`) whose list holds each reading (`history-reading`) with its chips; `expanded` is a `Set` signal (several open, reset on reload). Chips: `mat-chip-set` + `mat-chip.alert-chip[data-level]` (detail rows only: `describeTriggerWithLevel`; colours via `--mat-chip-*` tokens in `styles.css`); hooks `alert-history`, `history-turbine`, `history-detail`, `history-expand`, `history-reading`, `alert-chip`, `history-paginator`, `history-count`, `history-range-error`, `history-error`/`history-retry`, `history-empty`. Any other page can opt in the same way. States: `no-turbines`, `no-matches`, `turbine-count` (all matches, not the page). 25 per page (`turbines-paginator`), back to page 1 on a sort or filter change.
    - **Live order (`TurbineTable`):** cells, filters and the count follow every reading; the row *order* is a `linkedSignal` (`order`, positions of **all** `turbines`, so a row newly matching a filter shows at once in its last known place). Any new `turbines` (reading or clock tick) schedules `settleOrder`: `ORDER_QUIET_MS` (1 s) after the last one, `ORDER_MAX_HOLD_MS` (3 s) at most. `listKey` (ids, sort, filters) resets the order at once and clears the timers, so sort, filter and farm changes never wait or glide. Specs that check order after a live reading: `turbine-table-live.spec.ts` opens on real timers, then `vi.useFakeTimers()` + `TestBed.tick()` (`whenStable()` and harnesses would wait on a faked timer).
    - **`RowGlide` (`ui/row-glide.ts`, `table[appRowGlide]`):** `reorder(change)` = FLIP over `offsetTop` (scroll-safe), Web Animations `transform` on the `<tr>`, 500 ms, skipped with `prefers-reduced-motion` (CDK `MediaMatcher`). Moving a row in the DOM blurs its focused element and restarts its CSS animations (checked in Chromium), so it restores the focus and sets the new flash's `startTime` back. Don't use it with `stickyEnd`/sticky columns (sticky cells inside a transformed row) or without `[trackBy]`. `test-setup.ts` stubs `animate`/`getAnimations`; jsdom's `offsetTop` is always 0, so specs mock it.
    - **No Alert column** (removed): the page neither evaluates alert rules nor injects `AlertRulesStore` (so it makes no `GET /api/alert-configs`; specs `http.verify()` that). Alerts are evaluated by ingestion (`telemetry_alerts`) and shown on the turbine page's alerts chart and the Alerting History tab.
    - **`alerting/alert-text.ts`** (was `evaluate-alerts.ts`) only describes alerts for the UI (`LEVEL_SEVERITY`, `describeTrigger`, `describeTriggerWithLevel`); the evaluator lives in `@nextera/shared` (`triggeredAlerts`, used by ingestion).
  - **`/alerting`** redirects to `/alerting/history` (route `pathMatch: 'full'`). The former Active page (staleness list, `fleet/alerts.ts`, `FleetStore.alerts`) and the nav item's count badge were removed; staleness shows on the Turbines page, farm pages and the map.
  - **`/reporting` → `ReportingPage` (`reporting/`, proof of concept):** a Signal Form (`reportForm`, `[formRoot]` + a `(submit)` handler that marks the fields touched when invalid): `scope` (`mat-autocomplete` with `mat-optgroup` Farms / Turbines from `FleetStore.farms()`/`turbines()` via `scopeOptions`, filtered by `filterOptions` on what was typed (a `computed` over the model), `displayWith` the label; `required` + a `chooseOption` validator, so typed text alone is rejected), `start`/`end` (`mat-date-range-input`, `provideNativeDateAdapter()`, max today, both `required`; a root `validate` with `rangeError` from `core/days.ts` (kind `range`), shown in `report-range-error` once the form is touched or dirty). Run (`run-report`) → `ReportApi.telemetry` (`latestLoad`, like the History page) → `report-status`, `report-error`/`report-retry`, `report-empty`, StatTiles (`report-readings`/`-turbines`/`-alerts`), charts (`LineChart` per `METRICS` from `fleet/metrics.ts` + an alerts chart; `reportSeries` in `reporting/report.ts`: a farm aggregates per timestamp, power summed and the rest averaged, alerts summed with turbine-prefixed lines), `report-table` (50/page; `turbine` column only for farms; alerts cell = worst `AlertLevelBadge` + count + `matTooltip`), `download-csv` (`toCsv` RFC 4180 with telemetry.csv columns + `alerts` like `error:gearbox_temp_c above 120; …`, `csvFileName`, `downloadCsv` via Blob + object URL). The day helpers live in `core/days.ts` (shared with the History page). A zone change re-runs a report that was run (same calendar days); `csvFileName(report, zone)` names the days in the zone, while the CSV rows keep ISO UTC timestamps.
  - **Alerting tabs (`alerting/alerting-tabs.ts`, `PageTabs`, tablist "Alerting"):** "History" (`/alerting/history`) and "Rules" (`/alerting/rules`), routed Material tabs with `aria-selected` (History uses `<app-alerting-tabs fill>` to keep its window-high flex chain; hooks `alerting-tab-history|rules`). The side nav's Alerting (`/alerting`) stays current on both (prefix match).
  - **Alert rules state (`alerting/alert-rules.store.ts`, `AlertRulesStore`):** the one copy of the rules, provided by `FleetShell` next to `FleetStore`, created when a page first injects it (Rules page, Turbines table). `rules`, `loading` (until the first response), `failed` (latest load failed; the last rules are kept), `reload()`. Loads via `AlertConfigApi` (`alerting/alert-config-api.service.ts`) through `latestLoad<void, AlertConfig[]>` (`rules` = its value or `[]`, `loading` = no value yet and not failed; stale responses never win), and an `effect` on `FleetStore.alertConfigVersion` reloads it on every `alert-config.changed`. Route specs must flush its `GET …/alert-configs` (`openFleet(...).http`) on pages that use it.
  - **`/alerting/rules` → `AlertRulesPage` (`alerting/alert-rules-page.ts` + `.html`):** the thresholds from `AlertRulesStore` (labels/units in `alert-config.model.ts`). Table (`rule` rows with `data-level`; metric label + unit, condition, threshold right-aligned, level pill `AlertLevelBadge` (`alerting/alert-level-badge.ts`, `testId="rule-level"`, `data-level`; shared with the Turbines table: Info = neutral `bg-surface` + accent dot, Warning `bg-warn text-on-warn`, Error `bg-danger text-on-danger`); Edit/Delete buttons with `sr-only` rule names), `no-rules`, `rules-load-error` + Retry, `rules-notice` (`role=status`). Add/Edit in `RuleEditorDialog` (`alerting/rule-editor-dialog.ts`, host `rule-dialog`): a Signal Form (`ruleForm`: `metric`, `comparison`, `threshold: number | null` with `required` + a `finite` validator, `level`; native selects via `[formField]`; `[formRoot]` with a `submission` action, so `saving` = `submitting()` and a second submit is ignored), Material's default error state (invalid and touched; submitting marks every field touched: `<mat-error>` `rule-value-error`; for an empty required field `aria-required` instead of `aria-invalid`), server errors in `rule-error`; it does the POST/PATCH itself and closes with `{ action, rule }` only on success; a 409 is reworded (`rule-errors.ts`: `duplicateMessage`, `errorMessage`, `statusOf`) and reloads the page's `AlertRulesStore`. The editor also has an **Enabled** `mat-slide-toggle` (`rule-enabled`, `[formField]` through its CVA; on for new rules, prefilled when editing, sent in POST and PATCH); a 404 while editing shows `RULE_GONE_MESSAGE`. **Enabled column** (every role): owners+ get a `mat-slide-toggle` per row (`rule-enabled-toggle`, `hideIcon`, `aria-label` "Disable|Enable <describeRule>"; themed by `--mat-slide-toggle-*` tokens in `styles.css`): optimistic (`pending` map in the page, toggle `[disabled]` + `data-pending` while in flight), `AlertConfigApi.setEnabled` (PATCH `{ enabled }`), on success `AlertRulesStore.replace(rule)` (a `linkedSignal` over the load) + notice "Rule enabled|disabled: …" + reload, on failure rollback + `rules-toggle-error` (role=alert, `toggleErrorMessage`) + reload. Viewers see "Enabled" (`rule-enabled-state`). A disabled rule has a "Disabled" pill (`rule-disabled`) and a muted row (`data-enabled="false"` sets `--mat-table-row-item-label-text-color`). Delete confirms in `DeleteRuleDialog` (`delete-dialog`, Cancel focused via `cdkFocusInitial`, `confirm-delete`; closes with `'deleted' | 'disabled'`; a 404 counts as done). A **409 on that DELETE** = readings triggered the rule, mapped by status, never by the API's text (it names the uuid): title "This rule can’t be deleted", `delete-triggered` (`triggeredMessage(enabled)`), and `disable-rule` (PATCH `enabled: false`, closes `'disabled'`) or, if already disabled, only `close-delete`; focus moves to that button. Other errors use `errorMessage`. After a successful write the page announces it and calls `AlertRulesStore.reload()`; `alert-config.changed` reloads the store anyway.
- **Unallocated (`unallocated/`, owner+):** `/unallocated` → Pending / Blocked tabs (`PageTabs`, like Alerting). Each page provides `UnallocatedStore` (`latestLoad`, an `UNALLOCATED_STATUS` token, reloads on `FleetStore.unallocatedVersion`) and `UnallocatedActions` (notices, reloads, errors; a 404 means "already resolved elsewhere": close, notice, reload; a 409 shows the message and reloads). Assign is a Signal Forms dialog (farm autocomplete from `scopeOptions`/`filterOptions`, coordinates both-or-neither). Move and Block share `unallocated-confirm-dialog.ts`. Keep and Unblock are direct actions. `fleet.changed` → `FleetStore.reloadFleet(turbineId)` marks the turbine as announced, so its imported `telemetry.received` (sent right after) passes the unlisted-turbine guard before the farms reload. The announcement ends when a reload sent after it succeeds. Shared HTTP error text: `core/http-errors.ts` (`errorMessage`, `statusOf`). `stalenessOf` accepts anything with a `timestamp`. Expandable rows use the `tr.detail-row` class in `styles.css`.
