# apps/web: @defer

- **`@defer` (heavy chunks off the route's critical path):** only for a heavy dependency that the first paint doesn't need. Routes are already lazy, so a block only pays off when it splits something big off the route chunk. Current blocks: the Leaflet `MapView` (overview and farm page: `on viewport; prefetch on idle`), the turbine page's `ChartGroup` (ECharts, `on idle; prefetch on immediate`), Reporting's and the farm History and Weather history tabs' `ChartGroup` (`when hasCharts(); prefetch on idle`) and History's detail chips (`AlertChips`, `when isExpanded(…); prefetch on idle`). ECharts and Leaflet must stay out of every route chunk: check `ng build --stats-json` (`dist/web/browser-stats.json`) after a change. Each block costs ~6 KB gzip of Angular's defer runtime in the initial bundle, paid once.
  - **Defer local components only:** the compiler turns each deferred dependency into `import('<its specifier>')`. A package export (`MatChip`, `DecimalPipe`) keeps the whole package module (all of `@angular/common` ended up in the initial chunk), so wrap it in a local component (`alerting/alert-chips.ts`). The compiler drops an import declaration only when nothing else uses it, a type included: `import { MapView }` + `import type { MapMarker }`, never `import { MapMarker, MapView }` (that keeps Leaflet in the route chunk without an error).
  - **Triggers:** `on viewport` for below-the-fold content, `on idle` for near-the-fold content, `when <signal>` for content that only appears after some state (add `prefetch on idle` when it will be needed soon). Don't combine `on immediate` with a `@loading` block: Angular then skips the placeholder, and with `after` the slot stays empty until the skeleton appears. Use `on idle; prefetch on immediate` instead. Put the block where it exists from page load (the turbine page's sits beside the readings `@if`s, with its own `@if` inside), so its prefetch runs while the data loads. Defer a `ChartGroup` as a unit (shared crosshair/zoom), never single charts.
  - **States:** `@placeholder` keeps the rendered size, using Tailwind only and no `minimum` (`ChartSkeleton`, `charts/chart-skeleton.ts`: a card per chart, `{ title, lines }`, `h-56` plot; `MapPlaceholder`, `map/map-placeholder.ts`: `--map-height` + legend row, `state` `placeholder|loading|error`; History: the readings' times at chip height). The `@loading (after 100ms; minimum 300ms)` block is the same skeleton with a `role=status` "Loading …". `@error` shows a `role=alert` "Reload the page" message (a failed chunk usually means a new deployment) wherever the space would otherwise be blank. Headings that carry the page structure (h1, "Readings", "Charts") stay outside the block. Hooks: `chart-skeleton(-card)`, `charts-loading`, `charts-load-error`, `map-placeholder|loading|load-error` (+ `data-legend`), `history-detail-placeholder|loading|load-error`.
  - **Tests:** `test-setup.ts` stubs `IntersectionObserver`: every target is visible, reported a microtask later. `openFleet` preloads the deferred chunks (`preloadDeferredViews()`): a first evaluation slower than `after` would show `@loading`, and its `minimum` then waits on a timer that `whenStable()` doesn't track. Its `stable()` is `settle()` (`whenStable`, a task, `whenStable`), since `on idle` is an untracked `setTimeout` in jsdom and `on viewport` a microtask. Specs with a pending resource can't settle: use `renderDeferred(fixture)` (renders every block `Complete`). For placeholder/loading/error states, pass `openFleet(…, role, { deferBlockBehavior: DeferBlockBehavior.Manual })` (a separate `configureTestingModule` call is reset by `openFleet`'s own), then `await app.stable()`, `(await fixture.getDeferBlocks())[i].render(DeferBlockState.…)` and `stable()` again (`deferred-views.spec.ts`, and the Manual blocks in the Reporting/History specs).
